# 测试器械说明书

本文件仅验证文档处理，不是器械说明书，不包含可用于实际操作的医学信息。

## 安装流程

### 测试设备 A

这是设备 A 的独立章节。此段用于检查子块是否继承设备名称和父标题。测试字段一记录虚构编号 TEST-A；测试字段二记录虚构版本 A-1。文档切分应使这些字段与所属设备保持关联。

### 测试设备 B

这是设备 B 的独立章节。此段用于检查标题切分是否将两个设备的介绍分开。测试字段一记录虚构编号 TEST-B；测试字段二记录虚构版本 B-1。文档切分应使这些字段与所属设备保持关联。

## 长章节验证

LONG-01：本段验证章节的开头信息是否被完整保留。测试人员应在切分报告中查找这个编号，确认它仍属于“长章节验证”，并且能够追溯到测试文件的版本。这里的所有字段都是人工构造的测试文字，不应被用来描述任何真实医疗器械的性能或使用方法。

LONG-02：本段验证连续中文正文的处理。切分时应优先沿完整段落边界分组，只有单个段落本身过长时，才继续寻找句子边界。某个字段落在多个子块中是重叠策略可能出现的结果，但正文中的字符不应被丢弃，所属章节和原始资料链接也应继续保留。

LONG-03：本段验证位于章节中部的事实能否进入独立子块。测试字段“设备代号”为虚构的 TEST-LONG，测试字段“材料代号”为虚构的 MATERIAL-Z。两个字段只用于检查文本覆盖，不表示真实材料，也不应被解释成医疗器械的制造规格或临床适用范围。

LONG-04：本段验证修改配置后的可重复性。在同一编码器、同一输入文本和同一切分预算下，两次运行应得到一致的章节归属、块顺序及内容。将预算从八百调整为四百后，块数可能发生变化，但不能仅凭块数增加就判断检索准确率提高，还需要使用标注的问题比较证据覆盖。

LONG-05：本段验证子块中的来源继承。即使当前子块不包含整份文件的开头，检索结果仍需要说明它来自哪个文件、哪个版本及哪个章节。页码必须来自文档明确给出的标记；只有章节行范围时，应按行范围记录，不应把行号换算成推测的说明书页码。

LONG-06：本段验证章节之间的分离。设备 A 的标题和正文不应自动成为设备 B 的操作依据，多个产品名称只差一个字符时，更需要关注原始标题及元数据的归属。此处是软件测试要求，不提供器械选型、诊断或者治疗建议，也不替代专业人员核对原始资料。

LONG-07：本段验证输出报告的可审阅性。报告需要展示目标预算、实际 Token 数、是否存在超长块和切分规则版本，以便判断表格或者代码块是否为了保持完整而超过目标。超长标记是需要进一步检查的信号，不意味着这些内容已经被自动裁剪或丢弃。

LONG-08：本段验证章节尾部没有遗漏。字段 FINAL-MARKER 应出现在最终切分结果中；如果调整预算、重新运行后找不到该字段，需要检查原始文本与各子块的字符覆盖情况。测试结束后只应清理测试创建的记录，已有正式资料仍由各自的文件管理流程维护。
